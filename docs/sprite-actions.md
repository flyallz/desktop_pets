## v0.4.6 过渡画面

旧版抬爪等动作仅每秒更换约 2 张关键姿态，行走约 7 张，因此即使界面没有卡死，也会出现跳帧感。现在从同一套素材预计算过渡，成品不进行在线生成或实时光流推理。

| 动作 | 实际播放帧 |
|---|---:|
| 眨眼 | 24 |
| 向右 / 向左走 | 各 32 |
| 抬爪 | 49 |
| 伸懒腰 | 81 |
| 舔爪 | 113 |
| 张望 | 81 |
| 趴下 / 起身 | 41 |
| 睡觉 | 96 |

合计 549 帧，保存在 `assets/sprites/smooth/`，各图按每格 192 × 208、8 列排列。最后一行的空格不播放。

制作脚本使用双向 [OpenCV DIS 光流](https://docs.opencv.org/4.x/de/d4f/classcv_1_1DISOpticalFlow.html)估计局部位移，平滑位移场，并分别处理预乘颜色与轮廓距离，减少半透明重影。仅处理同一动作内的相邻姿态；不同姿态之间仍会有切换，素材本身的脸部和毛发差异也仍存在。

开发者需要重新计算时，可在独立 Python 环境中执行：

```powershell
python -m pip install -r tools/requirements-sprites.txt
python tools/prepare_sprite_transitions.py
.\build.ps1
```

依赖仅供制作素材，成品不需要安装 Python 或这些库。资源已经提交，正常编译不需要重复计算。

## 播放实现

`SpriteAnimation.cs` 在启动时解码各动作图集并缓存 549 个裁剪帧及透明度。动作版使用 `CompositionTarget.Rendering` 更新，步态与桌面移动使用同一时钟。每次更新只选择已有帧，使用 WPF 2D 绘制，不重复加载文件、不调整窗口尺寸，也不对左右行走素材额外镜像。鼠标命中从当前显示帧的透明度读取。

所有动作共用统一缩放与脚底基线。图片的生成差异仍会造成少量毛发、脸部与步态变化；这不是真实运动捕捉，不声称每个动作已达到无差异的连续视频效果。

旧照片造型保留原来的局部动画。自选照片只使用自己标记的眼睛、耳朵与尾巴，不会变成示例猫的全身动作。DeepSeek 设置和本地照片库继续复用，更新不会清空它们。

## 来源与授权

由 Codex 内置 imagegen 参考用户朋友的猫咪照片生成，狗狗精灵图只用于排列方式参考。生成结果原本带有棋盘背景，经已有的本地 IS-Net 模型去背景，再修正跨格轮廓、统一缩放和对齐。

## 验证边界

完整 EXE 的 `--self-test` 会保留旧版照片编辑与模拟聊天检查，并输出 `sprites/` 下 57 张实际 WPF 渲染图，检查每帧轮廓未裁切、透明度、鼠标命中、固定窗口尺寸、左右移动方向、手动动作、自动轮换、暂停/拖动/菜单/隐藏和睡醒流程。

像素对比检查固定使用 WPF 软件渲染；旧睡醒合成允许最多 64 个边缘像素出现不超过 2/255 的通道舍入差异，更大的变化仍会失败。普通运行沿用系统渲染设置。原造型计时器检查使用真实 WPF 调度器；动作版另用真实渲染事件检查连续 32 帧及窗口位移，输出三轮实际 WPF 行走截图。聊天只用本地模拟接口验证，本轮没有提供真实 DeepSeek API Key。其他电脑、实体鼠标操作及混合 DPI 多屏仍需要实机试用。

# 桌宠工坊：从内测走向可持续产品

这是实施建议与待验证假设，不是已经取得的经营结果。当前首批面向中国大陆用户，先做真实照片桌宠；Windows 和两种 Mac 架构使用同一份宠物包。

## 当前阶段的完成标准

用户能选自己的照片，看到结果，设置已有动作与陪伴功能，保存宠物包并重新打开。提供共用客户端与自动构建，保留原 Windows 样品。该阶段不要求账户、付款或公开照片社区。

一张照片的呼吸和点击反馈已能制作；完整步态需要多帧图片。多姿态 AI 生成必须单独验证“仍像原宠物”与帧间稳定性，不能把通用猫套皮当成定制完成。

## 下一步按什么顺序推进

1. **小范围真实使用。** 邀请约 10～20 位宠物主人，其中至少有 Windows、Mac M 系列与 Intel 各一种实际设备。记录制作是否完成、能否独立安装、是否认为像自己的宠物，以及第 7 天是否仍愿意使用。人数是建议，不是现有用户数。
2. **让动作制作更省事。** 先对每只宠物确认一个可辨认的基准形象，再生成睡觉、伸展、行走。提供预览、重做与人工修整入口。公开承诺的动作数量必须以实际通过质量检查的素材为准。
3. **上线有账户的私有制作服务。** 接入登录、私有对象存储、任务状态、用户删除与下载；按宠物包版本保持客户端兼容。图库公开分享须单独选择。
4. **验证成本后收款。** 先提供少量按次定制或动作包，明确交付物、失败处理、退款与客服边界；实际收款前完成适用的主体、支付渠道、域名和网站备案等要求。分类应按最终业务向服务商核实，不把“付费网站”简单等同于某一类许可。

每一步先看用户能否完成，而不是先增加栏目、积分或复杂会员等级。内测可以人工记录反馈；不默认采集屏幕、工作内容或完整使用日志。

## 建议的收费方式

基础的本地陪伴、已购买宠物包的离线运行与导出保持可用。可测试的付费项是新增动作、人工精修或额外定制服务。是否采用会员，等实际重复购买和持续成本出现后再决定。当前未确定价格，也不承诺无限生成。

每份交付的贡献毛利需要用真实账单计算：

收入 − 图片生成与重试费用 − 抠图/存储/流量 − 支付手续费 − 人工修整与客服时间成本 − 退款成本。

至少分开记录“首次成功”和“多次重做”的费用，采用每个订单的任务预算上限。不能只用一次成功生成的单价来定价。付费生成的任务、支付回调与交付应有幂等处理，失败不重复扣款；这些尚未实现。

## 4 核 4GB 服务器的用途

适合优先承载静态网页、轻量业务接口、少量内测账户和任务记录。安装包、照片与生成结果逐步放到对象存储。重型图片/视频生成交给外部按量服务或独立计算资源，客户端动画本地运行。

这是按架构做出的容量判断，尚未在该服务器部署或压测，不能据此承诺并发用户数。本轮未连接或修改该服务器。

早期不必部署 Kubernetes 或拆很多服务。可以从一个业务服务和一个数据库开始；抠图/生成任务限制并发并设置预算。当前 loopback 抠图辅助程序没有用户鉴权和公网限流，必须先改造才能上线，不能直接转发端口。

## Windows 与 Mac 的维护方式

用 React/Vite 保持制作器与渲染层一致，Electron 负责透明窗口、托盘、文件导入与系统通知。数据文件只存图片和设置，不允许执行脚本。这样未来增加动作或提醒，基本不用写三套产品。

Mac Universal 同时含 arm64 与 x64，但系统最低版本仍有限制。本版 Electron 44 要求 macOS 13 或以上；很旧的 Intel Mac 可能因此不受支持。使用官方运行时的维护版本，避免为了覆盖过旧系统长期保留没有安全更新的框架。[Electron 44](https://www.electronjs.org/blog/electron-44-0)、[Universal 格式](https://github.com/electron/universal)。

自动构建分别检查 Windows、M 系列和 Intel 原生启动；发行包里的两种架构另检查二进制。仍要实际测试鼠标穿透、拖动、缩放、多屏、全屏应用和低资源占用。Mac 正式发布使用 Developer ID 签名与公证；Apple 开发者计划的当前标准年费为 99 美元，地区定价和入会条件以 Apple 为准。[Apple 开发者计划](https://developer.apple.com/programs/enroll/)。

## 正式上线前需要落实的事项

- 确认名称和域名。部署在中国大陆时，按最终业务准备备案主体、内容和接入要求；现阶段没有这些资源也可先本机内测。[腾讯云网站备案说明](https://cloud.tencent.com/document/api/243/18907)。
- 把暂时的 Actions 附件改为稳定、可校验的签名安装包下载与版本更新；中国大陆访问体验另测。
- 写清用户照片的用途、保存时间、删除方式与生成服务的处理位置，默认私有。原始上传文件不进入公开 Git 仓库。
- 由仓库所有者确定代码及素材授权方式。公开仓库不自动等于已经授予开源许可，模型和第三方依赖的商用条款也需要按选用版本核对。

首个商业验证应回答两个问题：用户是否认为“这就是我的宠物”；为新增动作支付的费用能否覆盖稳定交付的成本。
